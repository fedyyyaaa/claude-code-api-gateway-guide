# 4. 接进自己的项目：VPS、鉴权和工具边界

这一篇开始讲生产架构。

先记住一句：

> **如果你的工具本来就在后端实现，就让它继续待在那里。**

这次要统一的是 Claude Code runtime，不需要顺手重写工具、数据库和记忆系统。

---

## 4.1 这里默认什么部署环境

后面的例子默认：

```text
浏览器 / App
      ↓
自己的后端
      ↓
VPS 上的 Claude Code 子进程
      ↓
OAuth / API Gateway
```

也就是：

- Linux VPS 或长期在线服务器；
- Claude Code 由后端拉起；
- 平时没有人在终端前按“允许”；
- 单用户 / 自用；
- 一次只让一个 turn 写入同一个 resident。

如果你只是本机终端用户，可以停在第 3 篇。

**多用户服务别直接照搬。** 多用户至少还要解决：

```text
user A credential ≠ user B credential
user A session    ≠ user B session
user A process    ≠ user B process
user A data       ≠ user B data
```

以及并发配额、租户权限、审计和资源隔离。

---

## 4.2 原来常见的结构

很多自建聊天项目会自然长成：

```text
API
 ↓
后端自己的 tool loop
 ↓
共享后端工具


Claude Code
 ↓
Claude Code agent loop
 ↓
共享后端工具
```

工具已经只有一套。

重复的是上面的 tool loop、session、历史投影和后台生成路径。

如果 Gateway 已经通过前两篇测试，可以收敛成：

```text
第三方 API Gateway ─┐
                    ├─ Claude Code runtime
Claude 订阅 OAuth ──┘
                           ↓
                     共享后端工具
```

自己的数据库、工具执行器、MCP、权限、记忆和 Context Planner 都可以继续保留。

## 4.3 VPS 上怎么放 OAuth 和 Gateway Key

### 订阅 OAuth

登录动作应该走 **Claude Code / Anthropic 自己的登录流程**，不要在你的网页里做一个“输入 Claude 账号”的框，也不要让后端代用户收集 claude.ai 登录凭据。

Claude Code 当前也提供长期 token 相关流程，例如 `claude setup-token`。如果你使用这类方式，令牌签发仍然应该发生在 Claude 自己的流程里。

在我们当前的单用户 VPS 实现中，已经取得的 OAuth token：

```text
server secret
      ↓
启动 Claude Code 子进程
      ↓
CLAUDE_CODE_OAUTH_TOKEN
```

只存在服务端。

如果 token 失效：

```text
明确报 auth error
      ↓
停止本轮
      ↓
重新走登录 / token 签发
```

**不要因为 OAuth 失效就偷偷切到会扣费的 API Gateway。**

### Gateway Key

Gateway Key 同样只放服务端：

```text
secret store / 受权限保护的配置
      ↓
启动子进程时注入环境变量
```

不要：

- 放 URL 查询参数；
- 放命令行参数；
- 发到浏览器再传回来；
- 打进日志；
- 提交到 Git。

## 4.4 provider 只在子进程边界选一次

推荐把 provider 选择放在**启动 Claude Code 子进程**的地方。

### 订阅模式

给进程：

```text
CLAUDE_CODE_OAUTH_TOKEN
```

同时清掉：

```text
ANTHROPIC_BASE_URL
ANTHROPIC_AUTH_TOKEN
ANTHROPIC_API_KEY
```

### API Gateway 模式

给进程：

```text
ANTHROPIC_BASE_URL
ANTHROPIC_AUTH_TOKEN
ANTHROPIC_MODEL
```

同时清掉：

```text
CLAUDE_CODE_OAUTH_TOKEN
ANTHROPIC_API_KEY
```

我们当前实现还会给 Gateway 模式加：

```text
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
CLAUDE_CODE_ATTRIBUTION_HEADER=0
```

以及把常见的：

```text
https://example.com/v1/messages
```

在这个边界转换成：

```text
https://example.com
```

供 `ANTHROPIC_BASE_URL` 使用。

**鉴权清理只在这个边界做一次。** 内部不要每层再猜一遍现在是哪家 provider。

## 4.5 无人值守时，工具权限要先收窄

这是 VPS 部署里非常重要的一块。

交互式终端里，Claude Code 可以弹窗问：

> 要不要执行 Bash？

headless 后端里没人替你按确认，所以必须提前决定工具面。

我们当前正式 Chat 的做法很窄：

```text
--tools ''
```

先关闭 Claude Code 内置的 Bash / Edit / 文件工具，然后只通过 MCP 暴露自己的后端能力，再用明确的 allowlist 放行。

也就是：

```text
Claude Code
  ↓
只能看到 / 调用我们主动暴露的 MCP 工具
  ↓
后端执行器
```

如果你自己的设计需要 Claude Code 内置工具，别直接开全。

Claude Code 当前权限文档里，一个更适合锁定型 headless agent 的思路是：

```text
permission mode = dontAsk
+
allowedTools = 明确白名单
```

没有进入白名单的工具直接拒绝，不等待人工确认。

特别注意：

> `allowedTools` **不能**拿来约束 `bypassPermissions`。

`bypassPermissions` 会批准到达这一层的其他工具调用，所以不要一边开 bypass，一边以为 allowlist 已经把 Bash / Write 锁住了。

官方权限说明：

https://code.claude.com/docs/zh-CN/agent-sdk/permissions

## 4.6 我们为什么关掉 Claude Code 自动压缩

我们的正式 Chat 自己有：

```text
ContextPlan
Continuity Chunk
Capacity / Window 切换
后端数据库历史
```

所以 Claude Code 如果再偷偷做一份自己的自动压缩，会出现两个上下文权威同时改历史：

```text
后端：我认为模型看到 A
Claude Code：我已经把 A 自动压成 B
```

后面切 provider、重启 resident 或做历史映射时，就很难证明两边看到的是同一份内容。

因此我们当前正式 Chat 在启动子进程时设置：

```text
DISABLE_AUTO_COMPACT=1
CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
```

只让自己的 ContextPlan / Continuity 管长期上下文。

### 关掉以后超长怎么办

不能只关，不接管。

我们的兜底是：

```text
上下文接近容量
      ↓
后端 ContextPlan / Capacity Swap
      ↓
选 Continuity Chunk + 近期原文
      ↓
启动新的 Claude Code generation / session
```

所以“关闭 auto compact”成立的前提是：**你已经有自己的上下文接管方案。**

如果你的项目没有 ContextPlan、Chunk 或其他换窗机制，别因为看到这篇教程就直接把 Claude Code 的 auto compact 关掉。

另外，这两个环境变量属于我们当前 Claude Code 运行时上实际使用的实现细节。升级 Claude Code 后要重新跑回归，不要把它们当成永远稳定的公开协议。

---

## 4.7 模型名不要偷偷猜

Gateway 的模型身份最好来自当前选中的 provider 配置。

例如：

```text
claude-opus-4-6
```

如果模型名拿不到，宁可报一个明确错误，也别悄悄退到某个默认模型。

否则你会很难判断：

> “这次请求到底是谁跑的？”

---

## 4.8 上下文系统不用跟着 provider 重写

如果你的项目已经有：

```text
Memory
Context Plan
Summary
Chunk
Window
Checkpoint
```

推荐继续保持：

```text
数据库
  ↓
自己的上下文系统
  ↓
Claude Code
  ↓
OAuth / API Gateway
```

provider 只决定模型请求往哪里发。

“这一轮应该看到哪些历史”继续由原来的系统决定。
