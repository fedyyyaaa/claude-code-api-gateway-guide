# 2. 第一关：让 `claude -p` 走第三方 API

目标很简单：

> 先证明 **Claude Code → Gateway → 模型** 这条路能走通。

这一关不碰工具、不碰 session，也不改你的项目。

---

## 2.1 需要替换的三项

先准备你自己的：

```text
ANTHROPIC_BASE_URL
ANTHROPIC_AUTH_TOKEN
ANTHROPIC_MODEL
```

Linux / macOS：

```bash
export ANTHROPIC_BASE_URL="https://your-gateway.example.com"
export ANTHROPIC_AUTH_TOKEN="YOUR_TEST_KEY"
export ANTHROPIC_MODEL="claude-opus-4-6"
```

这三项分别表示：

- `ANTHROPIC_BASE_URL`：请求要发到哪个 Gateway；
- `ANTHROPIC_AUTH_TOKEN`：Gateway 使用的 Bearer token；
- `ANTHROPIC_MODEL`：实际要请求的模型名。

Claude Code 当前官方环境变量文档明确写了：`ANTHROPIC_AUTH_TOKEN` 会作为 `Authorization: Bearer ...` 发送，`ANTHROPIC_BASE_URL` 用来把请求路由到 proxy / gateway。

如果你的服务商明确要求 `ANTHROPIC_API_KEY`，就按它的说明来。这个变量发送的是 `X-Api-Key`，而且在非交互 `-p` 模式里，只要它存在就会被使用。

官方参考（核对日期：**2026-11-13**）：

https://code.claude.com/docs/en/env-vars

---

## 2.2 建议保留的两个运行开关

本教程实测 Gateway 的 Claude Code 配置里还保留：

```bash
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
export CLAUDE_CODE_ATTRIBUTION_HEADER=0
```

用途分开看：

- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`：关闭 auto-update、telemetry、error reporting、release notes 等非必要网络流量，让 Gateway 探针更干净；
- `CLAUDE_CODE_ATTRIBUTION_HEADER=0`：关闭 Claude Code attribution header；这属于本教程实测 Gateway 配置的一部分，**不是所有 Gateway 都必须照抄的硬要求**。

如果你的 Gateway 官方文档给了 Claude Code 专用配置，优先按它的要求。

---

## 2.3 测试时把另一套鉴权清干净

如果这台机器以前登录过 Claude 订阅，建议当前探针把别的 credential 清掉：

```bash
unset CLAUDE_CODE_OAUTH_TOKEN
unset ANTHROPIC_API_KEY
```

这样做的目的很简单：

> **让这次测试只有一条可能的鉴权路径，方便确认请求到底走到哪里。**

这里不假设“只要登录过 Claude，就一定会同时发送两套凭据”。

真正需要注意的是：Claude Code 当前官方文档明确写了，`ANTHROPIC_API_KEY` 在非交互 `-p` 里只要存在就会使用，所以如果你这次想测的是 Bearer Gateway，最好把旧的 API key 清掉。

这些操作只影响当前 shell。

---

## 2.4 Windows PowerShell

需要替换的三项：

```powershell
$env:ANTHROPIC_BASE_URL="https://your-gateway.example.com"
$env:ANTHROPIC_AUTH_TOKEN="YOUR_TEST_KEY"
$env:ANTHROPIC_MODEL="claude-opus-4-6"
```

建议保留的运行开关：

```powershell
$env:CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC="1"
$env:CLAUDE_CODE_ATTRIBUTION_HEADER="0"
```

清掉当前测试不需要的鉴权：

```powershell
Remove-Item Env:CLAUDE_CODE_OAUTH_TOKEN -ErrorAction SilentlyContinue
Remove-Item Env:ANTHROPIC_API_KEY -ErrorAction SilentlyContinue
```

---

## 2.5 发一个最小请求

运行：

```bash
claude \
  --no-session-persistence \
  -p "只回复 GATEWAY_OK" \
  --output-format json
```

正常情况下，最终结果里应该出现：

```text
GATEWAY_OK
```

并且进程正常结束。

Linux / macOS 可以再看：

```bash
echo $?
```

返回：

```text
0
```

就是正常退出。

PowerShell 可以看：

```powershell
$LASTEXITCODE
```

---

## 2.6 回了 OK 以后，再去 Gateway 后台对一次账

**只看到 `GATEWAY_OK` 还不够。**

打开 Gateway 自己的后台，尽量核对：

- 请求时间是否和刚才一致；
- 实际模型是否正确；
- 如果后台提供 Key / credential 标签，是否是刚才那一枚测试 Key；
- 是否产生了对应的 usage / 额度 / 账单记录。

如果后台完全找不到对应请求，就不要直接宣布：

> “Gateway 路径验收成功。”

先继续查请求到底去了哪里。

---

## 2.7 怎么判断失败发生在哪里

### 返回 401 / 403 auth 错误

通常先检查：

- Key 对不对；
- Gateway 要的是 Bearer token 还是 `X-Api-Key`；
- 当前 shell 里是否还残留另一套 credential。

### 返回 404

优先检查 `ANTHROPIC_BASE_URL`。

很常见的错误是把：

```text
https://example.com/v1/messages
```

整个塞进 base URL，最后路径被重复拼接。

### 返回 quota / balance / insufficient credit

这类结果其实很有用。

它至少说明：

```text
Claude Code
  ↓
Gateway
  ↓
服务端账户系统
```

已经走到了服务端。

但它只能证明“链路可达”，还不能证明模型生成、工具和完整 agent loop 可用。

### 超时、流式事件错误、请求格式错误

这时更像 Gateway 的协议兼容问题。

先别改自己的项目，保持最小请求继续排查。

## 2.8 这一关通过后得到什么

你只证明了：

```text
Claude Code → Gateway → 模型 ✅
```

还没有证明：

```text
工具调用
多轮 agent loop
thinking
cache
session / resume
```

所以下一关要真的让 Claude Code 调一次工具。
