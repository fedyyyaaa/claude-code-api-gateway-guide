# 6. 兼容性与常见坑

“Anthropic-compatible” 和 “能完整跑 Claude Code” 不是完全同一件事。

普通文本能回，只是第一关。

---

## 6.1 推荐按这个顺序验证

```text
基础文本
  ↓
stream
  ↓
tools
  ↓
thinking
  ↓
cache
  ↓
session / resume
  ↓
长期 resident
```

一步一步来，哪一步坏了就停在那里排查。

不要一上来把整个生产系统都切过去。

---

## 6.2 Streaming

Claude Code 很依赖流式响应。

常见事件包括：

```text
message_start
content_block_start
content_block_delta
content_block_stop
message_delta
message_stop
```

有些 Gateway 普通请求能成功，但：

- 事件顺序不完整；
- 提前断流；
- 结束事件丢失；
- 字段被转换；

都会让 Claude Code 表现异常。

---

## 6.3 Tool Use

工具至少要正确处理：

```text
tool_use
tool_result
```

如果实际产品里会连续调用多个工具，最好再跑一次多轮工具测试。

另外，Claude Code 的权限行为会随版本变化。

当前官方故障排查文档已经专门提醒：升级 Claude Code / Agent SDK 后，如果 `claude -p` 没有明确传 permission mode，工具调用可能出现 denial。

所以升级以后：

**别只测“能回字”，一定重跑第 3 篇的真实工具探针。**

官方参考（核对日期：**2026-11-13**）：

- https://code.claude.com/docs/en/troubleshooting
- https://code.claude.com/docs/en/settings

---

## 6.4 Thinking

使用 thinking 模型时，要确认 Gateway 不会：

- 丢掉 thinking 相关字段；
- 改坏签名或结构；
- 在回放时返回不兼容格式。

如果你不需要 thinking，可以先关掉，把变量减少到最少。

---

## 6.5 Prompt Cache

长期运行时，缓存会直接影响成本和延迟。

建议观察：

```text
cache_creation_input_tokens
cache_read_input_tokens
```

“请求成功”不等于“缓存真的生效”。

切 provider、换模型或新开 session 后，首轮重新写一大段缓存是正常需要预期的成本。

---

## 6.6 `count_tokens` 缺失不一定致命

有些 Gateway 没完整实现 token counting endpoint。

Claude Code 在部分场景仍然可能正常运行，只是统计或估算不完整。

所以它更适合当兼容性检查项，不要单凭这一点直接判死刑。

---

## 6.7 鉴权优先级

最常见的幽灵问题之一：

> 明明配了第三方 API，结果请求还是跑去订阅了。

测试时尽量保证当前进程只存在一种 credential。

API 模式清掉：

```text
CLAUDE_CODE_OAUTH_TOKEN
ANTHROPIC_API_KEY
```

订阅模式清掉：

```text
ANTHROPIC_BASE_URL
ANTHROPIC_AUTH_TOKEN
ANTHROPIC_API_KEY
```

这样排错会轻松很多。

---

## 6.8 Claude Code 的 `costUSD` 不一定等于实扣

第三方 Gateway 可能有自己的：

- 汇率；
- 套餐；
- 折扣；
- 计费单位。

Claude Code 输出里的美元成本更适合看作**按已知列表价估算的参考值**。

最终请以服务商自己的账单为准。

---

## 6.9 版本漂移：哪些地方最容易变

Claude Code 会更新，Gateway 也会更新。

最值得警惕的变化有：

1. **权限默认值**：`-p` / headless tool call 会不会需要新的 permission mode；
2. **工具协议**：tool use / tool result 的字段与顺序；
3. **session 行为**：`--resume`、`--session-id`、transcript 格式；
4. **流式事件**：terminal event、usage、错误事件；
5. **自动压缩 / auto-memory**：关闭方式和行为；
6. **模型参数**：model id、thinking / effort 兼容方式；
7. **缓存**：cache header、TTL 和统计字段。

所以升级 Claude Code 前后，最少重新跑：

```text
探针 A：最小 claude -p
探针 B：真实工具回合
```

如果你还在生产上用 resident，再补：

```text
探针 C：连续两轮同 resident
探针 D：provider 切换后 cold start
探针 E：后台 one-shot -p
```

我们的教程顶部会一直保留实测版本，就是为了让后来的人知道：

> “这篇文章在哪个版本上真正跑过？”

---

## 6.10 自动压缩开关也属于版本敏感项

本文第 4 篇写到的：

```text
DISABLE_AUTO_COMPACT=1
CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
```

是当前项目在 Claude Code 2.1.280 上实际使用的启动环境。

它们服务于我们自己的 ContextPlan / Continuity 架构。

升级 Claude Code 后要重新确认：

- 变量还生效吗；
- 有没有新的官方配置入口；
- 关掉以后 session / resume 行为有没有变化。

如果你没有自己的上下文接管方案，不建议照抄。

---

## 6.11 条款和服务商规则

这个仓库只讨论技术接法。

Anthropic 当前法律与合规文档会区分订阅 OAuth 与开发者 API 使用，并限制第三方应用收集、中转 claude.ai 登录凭据。

本教程完整生产路径默认：

```text
单用户
自建
自用
自己的 VPS
自己的 provider credential
```

不覆盖“多用户共享一个人的订阅凭据”这一类设计。

请以最新官方文档为准（本文最后核对：**2026-11-13**）：

- https://code.claude.com/docs/en/legal-and-compliance
- https://code.claude.com/docs/en/settings

第三方 Gateway 是否允许 Claude Code、是否允许转发、怎么计费，也要看它自己的规则。
