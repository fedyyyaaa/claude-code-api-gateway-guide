# 6. 兼容性与常见坑

“Anthropic-compatible” 和 “能完整跑 Claude Code” 不是完全同一件事。

普通文本能回，只是第一关。

---

## 6.1 推荐按这个顺序验证

```text
基础文本
  ↓
stream
  ↓
tools
  ↓
thinking
  ↓
cache
  ↓
session / resume
```

一步一步来，哪一步坏了就停在那里排查。

不要一上来把整个生产系统都切过去。

---

## 6.2 Streaming

Claude Code 很依赖流式响应。

常见事件包括：

```text
message_start
content_block_start
content_block_delta
content_block_stop
message_delta
message_stop
```

有些 Gateway 普通请求能成功，但：

- 事件顺序不完整；
- 提前断流；
- 结束事件丢失；
- 字段被转换；

都会让 Claude Code 表现异常。

---

## 6.3 Tool Use

工具至少要正确处理：

```text
tool_use
tool_result
```

如果你实际产品里会连续调用多个工具，最好再跑一次多轮工具测试。

---

## 6.4 Thinking

使用 thinking 模型时，要确认 Gateway 不会：

- 丢掉 thinking 相关字段；
- 改坏签名或结构；
- 在回放时返回不兼容格式。

如果你不需要 thinking，可以先关掉，把变量减少到最少。

---

## 6.5 Prompt Cache

长期运行时，缓存会直接影响成本和延迟。

建议观察：

```text
cache_creation_input_tokens
cache_read_input_tokens
```

“请求成功”不等于“缓存真的生效”。

---

## 6.6 `count_tokens` 缺失不一定致命

有些 Gateway 没完整实现 token counting endpoint。

Claude Code 在部分场景仍然可能正常运行，只是统计或估算不完整。

所以它更适合当兼容性检查项，不要单凭这一点直接判死刑。

---

## 6.7 鉴权优先级

最常见的幽灵问题之一：

> 明明配了第三方 API，结果请求还是跑去订阅了。

测试时尽量保证当前进程只存在一种 credential。

API 模式清掉：

```text
CLAUDE_CODE_OAUTH_TOKEN
ANTHROPIC_API_KEY
```

订阅模式清掉：

```text
ANTHROPIC_BASE_URL
ANTHROPIC_AUTH_TOKEN
ANTHROPIC_API_KEY
```

这样排错会轻松很多。

---

## 6.8 Claude Code 的 `costUSD` 不一定等于实扣

第三方 Gateway 可能有自己的：

- 汇率；
- 套餐；
- 折扣；
- 计费单位。

Claude Code 输出里的美元成本更适合看作**按已知列表价估算的参考值**。

最终请以服务商自己的账单为准。

---

## 6.9 版本升级后重新跑探针

Claude Code 会更新。

第三方 Gateway 也会更新。

所以升级后最值得重跑的其实还是最开始那两条：

```text
最小 -p
真实工具回合
```

它们便宜、直接，而且能很快告诉你兼容性有没有变。

---

## 6.10 条款和服务商规则

这个仓库只讨论技术接法。

第三方 Gateway 是否允许某种调用方式、订阅账号是否允许某种集成方式，请以你实际使用时的 Anthropic 条款和服务商规则为准。
