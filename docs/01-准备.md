# 1. 开始之前：准备好三样东西

这一篇只做准备，不改你的项目。

你需要：

1. **一个能正常运行的 Claude Code**
2. **一个 Anthropic-compatible API Gateway**
3. **这个 Gateway 的测试 Key 和模型名**

建议第一次用临时 Key。测试完可以直接禁用，排错也更安心。

---

## 1.1 先确认 Claude Code 本身能启动

在终端里运行：

```bash
claude --version
```

能看到版本号就可以继续。

如果连 `claude` 命令都找不到，先把 Claude Code 安装好，再回来做下面的步骤。这个教程不处理 Claude Code 的安装问题。

---

## 1.2 找到 Gateway 的三个信息

你需要从服务商后台找到：

```text
API 地址
API Key
模型名
```

例如服务商可能写成：

```text
https://example.com/v1/messages
sk-xxxxxxxx
claude-opus-4-6
```

这里有一个常见小坑：

Claude Code 使用的是 `ANTHROPIC_BASE_URL`，它通常需要的是 **API 的 base**，例如：

```text
https://example.com
```

而不是完整的：

```text
https://example.com/v1/messages
```

但不同 Gateway 的路径规则可能不同。**如果服务商给了 Claude Code 专用配置，优先照服务商的写法。**

---

## 1.3 Key 不要写进仓库

教程里的 Key 永远写成：

```text
YOUR_TEST_KEY
```

真实 Key 请放在：

- 当前终端的环境变量；
- 服务器 secret；
- 你原来就有的密钥存储。

不要放进：

- README；
- Git commit；
- Issue / PR；
- 截图；
- 会长期保留的日志。

---

## 1.4 为什么推荐先在当前终端测试

环境变量只放在当前 shell 里，关掉终端就没了。

这样第一次测试最容易恢复，也不会污染你原来的 Claude Code 配置。
